#+title: lcntLibrary --- LCNT documents on an astro site

* Overview

Shared by every astro site on this system. A site publishes LCNT documents by *declaring* the releases
it shows: one spec per release in =<siteBase>/lcntSpecs/=, kept in the site's own git. An LCNT document,
released and exported with the lcnt =localWeb= method (bisos.lcnt, =lcntExportLocalWeb.cs=), writes that
spec. The site's own build (bisos.webCap, =astroProc.spcs -i contentBuild=, also run by =siteBuild=)
then lands each declared release in =<siteBase>/var/lcnt/= and generates pages of the site's content
tree from it: a Library tab listing the documents, and an access page for each release. Nothing in this
directory is specific to one site or one organization.

#+begin_example
document --lcntBuild--> Release/<rel>/  (committed in the document's BXO)
              |
              +--lcntExport (localWeb)--> <siteBase>/lcntSpecs/<pubcat>-<nu>-<rel>.pyl  (site's git)
                                                   |
     astroProc.spcs -i contentBuild  (siteBuild; run by the export)
          |  land (canonical path, else BXO) --> <siteBase>/var/lcnt/<class>/<nu>/<rel>/
          |  generate --> <siteBase>/content/tree/{lcnt/.../accessPage/, library/index_html/}
          v
     astro build --> the site
#+end_example

Why: a site must be rebuildable from scratch, on this host or on another one where it is possession
asserted (PALS). Everything outside the site's git (=var/lcnt/= and the generated nodes) is a cache
rebuilt from =lcntSpecs/= and the releases in their BXOs; nothing is pushed into a site that its
repository does not record. This file is the one place both contracts below are defined.

* The Spec Contract: =lcntSpecs/*.pyl=

Written by =bisos.lcnt= (=exportLocalWeb_csu.py=), read by =bisos.webCap= (=astroLcntLibrary_csu.py=).
One file per release, named from LCNT-INFO's =pubCategory= (else the class): =plpc-580003-0.1.pyl=. A
re-export of the same release replaces it; removing it removes the release from the site at its next
build.

It is one Python literal dictionary, formatted by =black=, read with =ast.literal_eval= (never =eval=;
there is no JSON anywhere). A file that is not a literal dictionary, or has another =specVersion=, is
refused.

| Key                             | Meaning                                                            |
|---------------------------------+--------------------------------------------------------------------|
| =specVersion=                   | =1=                                                                |
| =lcntClass=, =lcntNu=, =relTag= | the identity of the release                                        |
| =docNumber=                     | e.g. =PLPC-580003=                                                 |
| =releaseDir=                    | the release by its canonical path, =/de/sys/lcnt/...=, or =None=   |
| =lcntInfo=                      | the document's LCNT-INFO, canonical; for reference only            |
| =bxoKind=, =bxo=                | =bro= and =<org>/<repo>=, or =bpo= and its id                      |
| =bxoPath=                       | the release's path inside the BXO                                  |
| =bxoCommit=                     | the last commit of the release directory at export                 |
| =release=                       | the files: =pdfs= (name, build), =html= (dir), =htmlEntry=, =bibs= |
| =meta=                          | what an access page shows, from LCNT-INFO (see meta.pyl below)     |
| =exportSpec=, =exportedAt=      | which export spec wrote it, and when                               |

Finding the release on a host:
1. =releaseDir= when it exists (=/de/sys/lcnt= links into the activated BXOs, the same on every host).
2. Else the BXO: =/bisos/git/bxRepos/<bxo>/<bxoPath>= for a BRO, =/bxo/<bxo>/<bxoPath>= for a BPO.
3. Else a problem naming the BXO to activate. The build lands the other releases, then fails.

The BXO is the authority; =releaseDir= is the quick way in. When the release directory's last commit is
not =bxoCommit=, the release is landed with a note: it was changed since the export. The export itself
notes a release with uncommitted changes, since another host would get the older one.

* The Landing Contract: =var/lcnt/=

Rebuilt whole from =lcntSpecs/= on every =contentBuild= (built aside, renamed in). One directory per
release:

: <siteBase>/var/lcnt/<class>/<lcntNu>/<relTag>/

| =<class>=  | the LCNT class the document is in, from its path (=lgcc=, =lgpc=, ...)                |
| =*.pdf=    | the released pdf of each build spec named by the export spec                          |
| =html/=    | the HeVeA html, regular files only, with an =index.html= (an article only, see below) |
| =*.bib=    | the release's citation file, when there is one                                        |
| =meta.pyl= | what an access page shows (below)                                                     |

=meta.pyl= is the spec's =meta= plus what landing found. Placeholder values (="NA"=) are left out by the
export. The generator takes the class, number and release from the directory names, and tolerates every
other key being absent (the number stands in for a missing title).

| Key                                | Meaning                                                      |
|------------------------------------+--------------------------------------------------------------|
| =lcntClass=, =lcntNu=, =relTag=    | the identity of the release                                  |
| =docNumber=, =pubCategory=         | e.g. =PLPC-580003=, =PLPC=                                   |
| =title=, =subTitle=, =subSubTitle= | the titles                                                   |
| =authors=                          | a list of names                                              |
| =date=, =version=, =group=         | shown in the access page's table                             |
| =url=, =organization=, =seeAlso=   | optional, shown when present                                 |
| =description=                      | the short description                                        |
| =formats=                          | list of ={kind, path, bytes[, build]}=: =pdf=, =html=, =bib= |
| =files=, =pdfs=, =html=            | the landed files; =html= is the entry file, or =None=        |
| =lcntSpec=, =landedAt=             | the spec it was landed from, and when                        |

A =pdf= format carries =build=, the build spec's =buildName=. When a release has several pdfs the access
page labels each with its build (="PDF (art-8.5x11)"=, ="PDF (pres)"=).

* What the Generator Writes

=contentBuild= (or =astroSite.cs -i libraryGenerate <fqdn-or-base>=, which lands and generates the same
way) writes, into the site's content tree:

| =content/tree/lcnt/<class>/<nu>/<rel>/accessPage/= | a release's access page (the one to cite)    |
| =content/tree/lcnt/<class>/<nu>/accessPage/=       | the access page of the latest release        |
| =content/tree/library/index_html/=                 | the Library tab's page: one row per document |

They are ordinary content-tree nodes (parameter files and a =contentBody.html=), generated whole on each
run (built aside, renamed in) and kept out of git. The access page shows the document's vitals, the
available formats with sizes, the short description and, *for an article with html, the document itself*
embedded under "The document".

*Presentations.* For now a presentation is exported as pdf only, and its access page shows the formats
and no embedded document. Reveal.js presentations, and the rest of LCNT's multimedia facilities, are not
yet part of this export; they are to be added later.

* What a Site Needs

A site (the =astro-starter-bystar= starter has all of this) needs:

1. A =lcntSpecs/= directory beside =content/=, in git: its presence turns the Library on in
   =contentBuild=.
2. A =library= folder node in its content tree (=content/tree/library/=, objectType =folder=, a
   =folderTitle=): the tab. Its =index_html= is generated.
3. The page parameter =layoutBare= (=true=: the body is rendered as given, no footer, no tree heading),
   read by =contentTree.mjs= and used by =TreeLayout.astro=. The generated access pages set it.
4. A =.gitignore= listing =var/=, =content/tree/lcnt/= and =content/tree/library/index_html/=.
5. Serving of the landed files. =webVd_nginxSites.lcntVarLocations()= adds three =location= blocks to the
   site's nginx vhost, generated by =bisos.pals= (=pals-wvd.spcs=) or the site's =-wvd.pcs=: =/lcnt/= is
   served from =<siteBase>/var/lcnt/= (after the built pages), and =meta.pyl= is never served (404).
6. Optionally a stylesheet that sets =--libLabel=, =--libMuted= and =--libRowAlt=, to match the site's
   colors: =lcntLibrary.css= has fallbacks for all three.

On another host, the BXOs named by the site's specs must be activated (a BRO cloned under
=/bisos/git/bxRepos/=, a BPO activated under =/bxo/=) before the site builds.

* Files Here

- =lcntLibrary.css= --- the look of the access pages, copied by the generator into each page's =<style>=.
- The lander and generator are Python, standard library only: =bisos.webCap.astroLcntLibrary_csu=.

* Trying It

With a document that has an =Exports/localWeb= spec (=exportMethod= =localWeb=, =buildSpecs=,
=destinations=: site names on this system):

#+begin_src bash
lcntProc.sh -p extent="build+release" -i lcntBuild all
lcntProc.sh -i lcntExport ./LCNT-INFO/Exports/localWeb    # writes the spec, then rebuilds each site
#+end_src

The export prints, per destination, "specified <nu> <fqdn> <spec file>" and "rebuilt <fqdn> <base>", or
why it failed, and notes what a rebuild on another host would miss. Commit the new =lcntSpecs/= file in
the site's repository, and the release in the document's BXO.
